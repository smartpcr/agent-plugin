## What this document is

deepseek-harness (`dsh`) records its design decisions as **agent notes**: one Markdown
file per decision under `.agents/notes/`, sorted first by status (`implemented`,
`proposed`, `rejected`) and then by category (`architecture`, `bug-fix`, `feature` and
others). An implemented note states a problem and the decision taken, for example
`.agents/notes/implemented/feature/2026-09-09-web-sidebar-terminal.md:11`. A proposed
note states a problem and a proposal that upstream has not finished building, with
alternatives, acceptance criteria, risks and open questions, for example
`.agents/notes/proposed/feature/2026-06-30-pre-tool-input-rewrite.md:21`. Notes refer to
each other, and a later note may replace only part of an earlier one, for example
`.agents/notes/implemented/architecture/2026-11-13-ptc-output-truncation.md:15`.

The notes matter to the Go redesign because they are the only place where upstream says
*why* the product behaves as it does. The redesign is free to change mechanisms
([DH-ADR-2](../design.md#dh-adr-2)), so each note needs a judgement: keep the decision,
reach its goal another way, or leave it behind. The traceability ledger
([../trace/README.md](../trace/README.md)) holds one unit per current note, 464 in all.
This document covers the 116 units assigned to agent **D3**
(`trace/assignments/D3.jsonl`), and the same verdicts are written as ledger rows in
`trace/fragments/D3.jsonl`.

The batch holds 103 implemented notes and 13 proposed notes. It
holds no rejected notes.

Terms used below:

| Term | Meaning |
|---|---|
| Host | The `dsh` process that runs agents and tools and serves the user interface. |
| Session | One conversation, stored as an append-only log of events. |
| Agent | The live object that runs a session's turns. A subagent is an agent created by another agent. |
| Preset | A named composition of persona, tools and skills that an agent runs under. |
| Capability seam | Upstream's pattern of splitting a swappable capability into a contract, a provider and a consumer. |
| MCP | Model Context Protocol, the open protocol through which a server offers tools to a model host. |
| PTC | Programmatic tool calling: the model writes a TypeScript program that calls tools, instead of one tool call per step. |
| CUA | Computer Use: the experimental capability that drives desktop applications through accessibility and input APIs. |
| Peer | The authenticated identity of a caller of the host's web interface. |
| Island | A small self-contained piece of browser JavaScript inside a server-rendered page ([DH-ADR-3](../design.md#dh-adr-3)). |

## How to read the tables

There is one table per upstream category. Implemented notes come first, in the order of
the assignment file; proposed notes follow and are marked.

| Column | Content |
|---|---|
| Note | The note's title, linked to the file, and below it the path with the line of its `Decision` or `Proposal` heading. Paths are relative to the upstream root. Links assume the upstream checkout sits beside this repository as `deepseek-harness`. |
| Summary | The decision in one or two sentences, restated from the note. |
| Kind | What sort of decision it is: product architecture, product feature, bug fix, simplification, testing practice, development process or documentation. This is this document's classification, which can differ from the upstream folder. |
| Area | The upstream path the decision is mainly about. Empty when the note cuts across several packages. |
| First verdict | The ledger disposition proposed for the Go redesign (see below), with the global decision it rests on when there is one. |
| Why | The reason for the verdict. |

The Summary column reports what the note says. **The First verdict and Why columns are
inference**: they are this agent's judgement about the Go redesign, not something read
from upstream.

The four verdicts:

| Verdict | Meaning | Who finishes it |
|---|---|---|
| `ported` | The Go design should keep this decision. For a proposed note it means "adopt the idea"; the Why column says with what priority. | The area agent links it to a Go deliverable or decision. Rows are written without links on purpose, so the traceability check keeps them visible until that happens. |
| `replaced` | The goal stands, but the Go design reaches it by a different mechanism. The global decision that forces the change is linked: server-rendered HTML ([DH-ADR-3](../design.md#dh-adr-3)), compiled-in components and plugin processes ([DH-ADR-4](../design.md#dh-adr-4)), or freedom from upstream formats ([DH-ADR-2](../design.md#dh-adr-2)). | The area agent names the replacing mechanism. |
| `dropped` | The Go design should not do this. The decision that explains the drop is linked. | The area agent confirms or reopens. |
| `not-applicable` | The note is about upstream's development process, repository mechanics or npm tooling. | Final. |

## Patterns worth carrying into the Go design

These ten are the decisions in this batch that most deserve to survive the redesign
unchanged in substance. Each entry gives what upstream decided, why it matters for a Go
host, the cost it carries, and what an acceptance test should show. The reasoning is
inference; the cited notes are the source of the upstream facts.

### 1. Fail closed when nobody can answer

- **Upstream decision.** One approval service turns "may this action proceed?" into a
  closed one-shot outcome. Whoever owns a channel to a person registers as an answerer;
  with no answerer the outcome is `unavailable` and the tool call is denied.
  The approval seam — one-shot permission decisions over a waterfall of answerers at `.agents/notes/implemented/feature/2026-07-06-approval-seam.md:13`, extended by Auto review asks the user after a denial at `.agents/notes/implemented/feature/2026-09-24-auto-review-user-approval-fallback.md:11`.
- **Why keep it.** A headless or misconfigured deployment can never grant itself
  permission by default, and tool policy and sandbox escalation share one vocabulary and
  one audit trail.
- **Cost.** Every channel (web page, SDK callback, ACP bridge) must register an
  answerer, or its users see denials.
- **What to verify.** With no answerer composed, a tool call that needs approval is
  denied and the log records `unavailable`; with one composed, each outcome reaches the
  tool exactly once.

### 2. The kernel, not the writer, owns the session write lock

- **Upstream decision.** A session's writer holds a kernel lock for the life of its
  write handle (`flock` on POSIX, a named semaphore on Windows). The kernel releases it
  when the process dies; a stuck but living holder keeps it. cross-process session write lease at `.agents/notes/implemented/feature/2026-08-31-cross-process-session-write-lease.md:11`.
- **Why keep it.** Two processes appending to one log tear it. An arbiter outside every
  writer survives all crash modes and needs no expiry timers or heartbeat files.
- **Cost.** A wedged process blocks its session until it exits. Upstream accepted this,
  because taking the lock away from a stalled writer would let its later appends corrupt
  the log.
- **What to verify.** A second process fails to open the session for writing with a
  named error; after the first process is killed, the second succeeds without cleanup.

### 3. Treat the cached request prefix as a budget

- **Upstream decision.** Three notes protect the provider's prefix cache: a changed
  system prompt is appended later in history instead of rewriting message 0
  (In-history system prompt replacement for cache-stable prompt changes at `.agents/notes/implemented/feature/2026-09-02-in-history-system-prompt-replacement.md:15`); the first message is rewritten at a series start only when its text must
  move (A series start with an unchanged prompt keeps the surviving system node at `.agents/notes/implemented/bug-fix/2026-10-22-series-start-unchanged-prompt-prefix.md:13`); and values that differ per process, such as a port or a checkout
  path, never enter the system prompt (Process-specific checkout path and Web URL move to runtime context at `.agents/notes/implemented/bug-fix/2026-10-11-process-specific-prompt-values-in-runtime-context.md:19`).
- **Why keep it.** In long agent sessions a prefix-cache miss costs the whole prompt
  again. These rules are about bytes sent to the provider and do not depend on the host
  language.
- **Cost.** The request is no longer a simple function of "current prompt plus
  history"; the projection that builds it has rules that need their own tests.
- **What to verify.** Across a prompt change, a compaction and a host restart on a
  different port, the first messages of consecutive requests stay byte-identical.

### 4. The host decides, the page displays

- **Upstream decision.** Several notes move decisions out of the browser: the host
  computes every state, label and button of a connector account (One Host registry and one browser half for connector accounts at `.agents/notes/implemented/architecture/2026-11-06-connector-account-registry.md:11`); the host
  assembles one streamed state for the change-request panel (Change request panel and worktree Sessions at `.agents/notes/implemented/feature/2026-10-09-forge-panel.md:11`); reading marks
  live on the host so all browsers agree (Host-memory Session reading state at `.agents/notes/implemented/feature/2026-10-23-session-reading-memory.md:11`); and preferences are host
  settings for every authenticated browser (Share Host preferences with every authenticated browser at `.agents/notes/implemented/bug-fix/2026-09-15-authenticated-browser-host-preferences.md:11`).
- **Why keep it.** This is the shape [DH-ADR-3](../design.md#dh-adr-3) needs. Where
  upstream already works this way, the Go UI is a template over an existing host
  contract and not a rewrite of client logic.
- **Cost.** More host state per connected page, and the host must push updates.
- **What to verify.** Two browsers on one host show the same account state, panel
  state and unread marks without either holding state of its own.

### 5. Parallel tool calls are opt-in per call, and doubt means exclusive

- **Upstream decision.** A tool may supply a pure, synchronous classifier over its own
  arguments. Only an explicit `true` lets the call overlap with siblings; a missing
  classifier, invalid arguments or a thrown error make it exclusive. Parallel tool-call execution by per-call safety at `.agents/notes/implemented/feature/2026-07-10-parallel-tool-call-execution.md:15`.
- **Why keep it.** It removes the latency of independent reads without the scheduler
  having to compare calls, and a mistake degrades to serial execution, not to a race.
- **Cost.** Rules that depend on two calls together ("safe when the paths differ")
  cannot be expressed, so such calls stay serial.
- **What to verify.** Two read calls in one message overlap in time; a write beside a
  read does not; every started call still has its audit event in the log.

### 6. A program with side effects is truncated, never cancelled, and chooses its own output

- **Upstream decision.** When a program's captured output overflows, the runtime keeps
  a prefix and marks it truncated instead of stopping the program (PTC output truncation without execution cancellation at `.agents/notes/implemented/architecture/2026-11-13-ptc-output-truncation.md:11`). The
  program selects what the model sees with `inspect`, and its final value is discarded
  (Explicit text and image output in PTC at `.agents/notes/implemented/architecture/2026-11-09-explicit-ptc-output.md:11`). Tool bindings return canonical JSON and reject with real errors
  (Typed tool returns in PTC mode at `.agents/notes/implemented/feature/2026-07-20-ptc-typed-tool-returns.md:15`).
- **Why keep it.** A program cancelled half-way leaves the caller unable to tell which
  external actions ran. Explicit output keeps intermediate results out of the context
  window.
- **Cost.** A runaway program keeps running until its deadline or heap limit, which
  therefore must exist and be tested.
- **What to verify.** A program that prints far past its budget still completes its
  last tool call and reports `outputTruncated`; a failing program keeps its failure kind.

### 7. Authority comes from the operator and from recorded sources, never from the model

- **Upstream decision.** The permission mode of an external product subagent is fixed
  in the deployment profile and absent from the tool schema (Product subagents use Profile-selected non-interactive permissions at `.agents/notes/implemented/feature/2026-08-15-product-subagent-noninteractive-permissions.md:13`). The model
  routes a parent may pick for a child are an explicit user-approved list
  (User-authorized subagent model routes at `.agents/notes/implemented/feature/2026-08-24-user-authorized-subagent-model-routes.md:11`). The automatic reviewer treats text as instruction only when its
  recorded source is the user (Headless caller authority for Auto review at `.agents/notes/implemented/feature/2026-10-18-headless-auto-review.md:11`).
- **Why keep it.** Each rule closes a path by which a model, or text injected into its
  context, could raise its own authority.
- **Cost.** Less flexibility per call: changing a mode or adding a model is an operator
  or user action.
- **What to verify.** No tool schema carries a permission or unrestricted model field,
  and a tool result that says "the user approves" does not change a review outcome.

### 8. Derive from the session log instead of keeping a second store

- **Upstream decision.** Change-request bindings are a projection over logged shell
  calls (Session change request bindings at `.agents/notes/implemented/feature/2026-10-09-session-change-request-bindings.md:11`). Job start and settlement are logged facts with stable ids
  (Persist owned job lifecycle facts at `.agents/notes/implemented/bug-fix/2026-09-30-job-session-lifecycle.md:11`). The workspace root is an event, and the model-facing directory cursor
  was removed (Session workspace root at `.agents/notes/implemented/architecture/2026-11-03-session-workspace-root.md:11`).
- **Why keep it.** Fork, resume and replay then need no extra migration, and there is
  one source of truth to audit. This is the event-sourced session model at work.
- **Cost.** Projections must be cached for sessions that are not loaded, and a
  projection that parses command lines is only as good as its patterns.
- **What to verify.** A forked session shows the same bindings and job history as its
  source up to the fork point, with no store other than the log.

### 9. Disclose tools on demand

- **Upstream decision.** An MCP server can keep its tools out of the registry behind
  one loader tool and a short catalog (On-demand MCP tool loading at `.agents/notes/implemented/feature/2026-10-08-mcp-on-demand-tool-loading.md:13`). A proposal generalizes this to two
  dimensions per tool, reachability and initial disclosure (Tool reachability and initial disclosure at `.agents/notes/proposed/architecture/2026-11-18-tool-reachability-and-initial-disclosure.md:11`).
- **Why keep it.** One hosted server can add more than 200,000 characters of tool
  definitions to every request. With MCP as the tool protocol for plugins
  ([DH-ADR-4](../design.md#dh-adr-4)), the Go host will meet this more often than
  upstream does.
- **Cost.** The model spends a step loading tools, and the catalog text becomes part of
  the system prompt, where changes to it cost prefix cache (see pattern 3).
- **What to verify.** With an on-demand server connected, the request carries one
  loader tool and no server tool schema until the model loads one.

### 10. Windows confinement needs all three edits

- **Upstream decision.** The Windows sandbox uses a write-restricted token with
  capability SIDs (Windows sandbox rung: raw ACL restricted tokens over mxc and AppContainer at `.agents/notes/implemented/feature/2026-08-08-windows-acl-restricted-token-sandbox.md:11`), and every grant adds a deny of `FILE_DELETE_CHILD` and a
  Low integrity label, with the token lowered to Low (Windows sandbox delete confinement: mandatory integrity plus an ambient-delete deny at `.agents/notes/implemented/feature/2026-09-19-windows-acl-mandatory-integrity-confinement.md:11`).
- **Why keep it.** The second note exists because the first allowed deleting files
  outside the workspace through the parent directory's delete right. The notes record
  why each of the three edits is needed, which is expensive knowledge to rediscover.
- **Cost.** Granted directories carry modified ACLs and labels that must be removed on
  cleanup; a crash can leave them behind, so the Go sandbox needs a recovery pass.
- **What to verify.** On a real Windows host, a confined process can write and delete
  inside its roots and can neither write nor delete outside them, and the ACLs and
  labels of the granted directories are restored afterwards.

## Open questions for the area agents

These came up while classifying. Items 1 to 3 and 9 have since been settled by the
owner; the others are answered by the area specifications named.

1. **Program runtime.** PTC and the Computer Use program tool keep a JavaScript runtime
   as a separate process (PTC mode — the model writes TypeScript against the tool registry (`.agents/notes/implemented/feature/2026-06-15-ptc.md`), CUA programs outside the PTC preset (`.agents/notes/implemented/architecture/2026-11-09-cua-program-tool.md`)). Settled by the owner: the Go
   distribution bundles no runtime and requires none. A model-written script is an
   ordinary command that calls tools through `dsh tool call`
   ([DH-ADR-8](../design.md#dh-adr-8)), and computer use comes only from an external
   MCP server the operator installs ([DH-ADR-19](../design.md#dh-adr-19)).
2. **Office engine.** The Office tools load LibreOffice Kit inside the Node host
   (On-demand Office tools for rendering, conversion, and recalculation (`.agents/notes/implemented/architecture/2026-10-31-native-office-tool.md`)). Settled by the owner: an operator-installed LibreOffice run
   headless as a child process ([DH-ADR-20](../design.md#dh-adr-20)).
3. **Desktop browser pane.** Settled by the owner: dropped
   ([DH-ADR-18](../design.md#dh-adr-18)).
4. **Docking surface.** Whether the right column keeps free docking and floating panels
   decides the fate of two notes (Right Sidebar docking infrastructure (`.agents/notes/implemented/feature/2026-09-04-right-sidebar-docking-infrastructure.md`), Spring-based edge recovery for floating dock panels (`.agents/notes/implemented/feature/2026-10-21-floating-window-edge-recovery.md`)).
5. **Spreadsheet preview.** Parse on the host, or keep a JavaScript grid as an island
   (Browser Excel preview with saved formula results (`.agents/notes/implemented/feature/2026-09-16-browser-excel-preview.md`)).
6. **Pseudo-terminal on Windows.** The Go PTY library choice must be checked against the
   two findings in A seen prompt marker keeps its own tail grace (`.agents/notes/implemented/bug-fix/2026-09-27-pwsh-prompt-tail-grace.md`) and Windows persistent PTYs use the console host node-pty ships (`.agents/notes/implemented/bug-fix/2026-09-28-pty-bundled-console-host.md`).
7. **External product subagents.** The Claude Code provider depends on an npm SDK
   (Product subagents use Profile-selected non-interactive permissions (`.agents/notes/implemented/feature/2026-08-15-product-subagent-noninteractive-permissions.md`)); the Go provider needs another integration path.
8. **Reading state durability.** Reading records are in memory only upstream
   (Host-memory Session reading state (`.agents/notes/implemented/feature/2026-10-23-session-reading-memory.md`)); a host restart forgets them.
9. **Proposals not adopted.** Two unbuilt upstream proposals are marked `dropped`
   against [DH-ADR-4](../design.md#dh-adr-4), and one deferred proposal (Deferred Desktop update extensions (`.agents/notes/proposed/feature/2026-09-08-desktop-update-extensions.md`)) is
   marked `ported` in the sense of "keep deferring". The coordinator may prefer one
   recorded decision that covers upstream proposals the Go design does not take up.
